# /nf-deep - 深度并行分析

## 目的
对于复杂问题，使用 Agent 工具从多个角度**真正并行**分析。

## 何时使用
- 复杂的架构决策
- 没有明显解决方案的问题
- 不熟悉的技术/领域
- 需要彻底探索的高影响决策

## 执行方式

**重要：使用 Agent 工具并行 spawn 多个 Explore agent，实现真正的并行分析。**

### 1. 清晰定义问题
```
问题：[我们试图回答什么？]
上下文：[相关 NF 或情况]
```

### 2. 并行 spawn 分析 Agent

根据问题选择适用的角度（不必全部使用），**在一条消息中同时发起多个 Agent 调用**：

```
使用 Agent 工具，subagent_type="Explore"，同时 spawn 以下 agent：

Agent 1 - 算法角度：
  "分析 [问题] 的算法方面：性能影响、时间/空间复杂度、可扩展性。
   搜索项目中相关的代码实现，评估当前方案的效率。"

Agent 2 - 结构角度：
  "分析 [问题] 的架构方面：代码组织、设计模式、关注点分离。
   检查项目结构，评估现有架构是否支持该变更。"

Agent 3 - 渐进角度：
  "分析 [问题] 的迁移路径：向后兼容性、发布策略、渐进式实施方案。
   检查现有 API/接口，评估变更的影响范围。"

Agent 4 - 环境角度：
  "分析 [问题] 的依赖和环境方面：新库/服务需求、部署变更、基础设施影响。
   检查项目依赖配置，评估引入新依赖的风险。"

Agent 5 - 安全角度（如适用）：
  "分析 [问题] 的安全方面：攻击面、数据保护、认证/授权影响。
   搜索项目中的安全相关代码，评估潜在风险。"
```

### 3. 综合发现
等待所有 Agent 返回结果后，创建汇总表：

| 角度 | 关键洞察 | 风险 | 建议 |
|------|----------|------|------|
| 算法 | ... | ... | ... |
| 结构 | ... | ... | ... |
| 渐进 | ... | ... | ... |
| 环境 | ... | ... | ... |
| 安全 | ... | ... | ... |

### 4. 给出建议
```markdown
## 推荐方案
[清晰的建议及理由]

## 置信度
[高/中/低] + 理由

## 下一步
1. [行动 1]
2. [行动 2]
```

## 提示

- 如果不相关，不要强制使用所有 5 个角度
- 目标是可操作的洞察，不只是分析
- 所有 Agent 调用应在**同一条消息**中发出以实现并行
- 每个 Agent 应聚焦自己的角度，不需要面面俱到
