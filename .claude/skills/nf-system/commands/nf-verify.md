# /nf-verify - 验证 NF 实现

## 目的
审查代码、创建验证计划并执行测试。

## 步骤

### 1. 检查 Git 状态
```bash
git status
git diff --stat
```
向用户显示修改了哪些文件。

### 2. 审查修改的文件
对每个修改的文件检查：
- [ ] 边界情况处理
- [ ] 类型正确（如适用）
- [ ] 错误处理存在
- [ ] 没有遗留 console.log / print 调试语句
- [ ] 没有需要处理的 TODO 注释
- [ ] 代码符合项目约定（CLAUDE.md）
- [ ] 没有敏感文件（.env, credentials, secrets）被修改

### 3. 安全提交
**重要：不要使用 `git add .`，防止意外提交敏感或无关文件。**

1. 列出所有变更文件，向用户确认哪些需要提交
2. 排除以下文件（如果出现在变更中）：
   - `.env`、`.env.*` 等环境配置文件
   - 包含密钥/凭证的文件
   - IDE 配置文件（`.idea/`、`.vscode/`）
   - 系统文件（`.DS_Store`、`Thumbs.db`）
   - 依赖目录（`node_modules/`、`__pycache__/`、`target/`、`vendor/`）
3. 逐个添加确认后的文件：
   ```bash
   git add <file1> <file2> ...
   git commit -m "NF-XXX: [简短描述]"
   ```

### 4. 创建验证计划
根据 NF 的验证部分和项目实际使用的测试工具：
```markdown
## NF-XXX 验证计划

### 自动化测试
1. 运行测试：[根据项目检测的测试命令]
2. 检查覆盖率：[根据项目检测的覆盖率命令]

### 手动测试
1. [步骤 1]
2. [步骤 2]

### 性能（如适用）
- [ ] 关键指标达标
```

### 5. 执行验证
运行测试并报告结果：
```
✅ 测试：XX/XX 通过
⚠️  手动：需要用户验证的项目
```

### 6. 建议下一步
```
验证完成。准备关闭 NF-XXX？
运行：/nf-close NF-XXX
```

## 边界情况

- 测试失败 → 诊断并建议修复
- 检测到无关更改 → 要求用户分离提交
- 存在敏感文件变更 → 警告用户，建议添加到 .gitignore
