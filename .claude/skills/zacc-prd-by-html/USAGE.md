# zacc-prd-by-html 使用指南

## 概述

`zacc-prd-by-html` 从产品原型文件（HTML/CSS/JS）反向推导并生成完整的 PRD 产品需求文档。通过六维度结构化提取，将可视化产品形态转化为可执行的产品文档。

## 适用场景

- 产品经理已产出 HTML 原型，需要补写 PRD 文档
- 接手已有原型项目，需要快速了解产品需求
- 原型迭代后需要同步更新 PRD

## 支持的输入类型

| 输入类型 | 示例 |
|----------|------|
| 单个 HTML 文件 | `prototype/index.html` |
| HTML 目录 | `prototype/`（包含多个 .html 文件） |
| ZIP 压缩包 | `prototype.zip` |
| 远程 URL | `https://example.com/prototype/` |

> 目前不支持 PDF、图片、Figma 链接。建议导出为 HTML 后使用。

## 使用方式

在 Claude Code 中执行：

```
/zacc-prd-by-html prototype/xxx.html
/zacc-prd-by-html prototype/
/zacc-prd-by-html prototype.zip
/zacc-prd-by-html https://example.com/prototype/
```

若不带参数，技能会询问原型文件路径。

## Plan Mode 审批

本技能 **必须以 Plan Mode 执行**，确保 PRD 文档经过用户审批后才落盘：

1. 技能触发后自动进入 Plan Mode
2. 全部分析在 Plan Mode 内完成（不写入任何项目文件）
3. 分析完成后退出 Plan Mode，提交 PRD 内容等待用户审批
4. 用户审批通过后才写入文件

## 执行流程

| 步骤 | 说明 |
|------|------|
| 步骤 0 | 输入类型门禁：判定输入类型（HTML/目录/ZIP/URL） |
| 步骤 1 | 输入预处理：读取内容、处理编码和资源完整性 |
| 步骤 2 | 页面关系建模：构建导航图谱（多文件时） |
| 步骤 3 | 六维度信息提取：产品概述、用户流程、信息架构、功能需求、交互规范、数据需求 |
| 步骤 4 | PRD 文档生成：按模板组装，只生成有提取结果的章节 |
| 步骤 5 | 写入 PRD 文件：审批后落盘 |

## 六维度提取

| 维度 | 提取来源 | 输出 |
|------|----------|------|
| 产品概述 | `<title>`、`<h1>`、logo、meta | 产品名称、定位、目标用户 |
| 用户流程 | `<a>`、`<button>`、`<form>`、JS 跳转 | 用户旅程图、导航关系 |
| 信息架构 | DOM 层级、CSS class、标题层级 | 模块结构、导航体系 |
| 功能需求 | `<form>`、`<input>`、`<table>`、列表 | 功能模块、用户故事、规则 |
| 交互规范 | CSS 变量、样式属性、JS 动画 | 色彩、字体、组件规范 |
| 数据需求 | fetch/axios、localStorage、表单字段 | 数据实体、流转关系 |

## 输出文件

| 文件 | 默认位置 | 说明 |
|------|----------|------|
| PRD 文档 | `docs/prd/{产品名}.md` | 产品需求文档（用户可指定路径） |

文件已存在时提供三个选项：覆盖（自动备份）、追加日期后缀、取消。

## 与其他技能的衔接

| 衔接场景 | 说明 |
|----------|------|
| PRD → 技术方案 | 生成 PRD 后可执行 `/task-init`，将 PRD 作为需求输入 |
| PRD → 原型 | 可结合 `zacc-prd-init-html` 根据 PRD 生成 HTML 原型 |

## 核心原则

- **不臆测**：原型中不存在的信息一律标注「待确认」
- **可追溯**：每个提取结论标注原型来源（文件路径 + 元素定位）
- **结构完整**：即使内容为空也保留章节框架
- **置信度标注**：高（明确对应）/ 中（合理推断）/ 低（经验假设）

## 常见问题

**Q: 多页面原型的分析速度如何？**
A: ≤5 页面串行分析；>5 页面按页面分配 Agent 并行分析（最多 4 个 Agent）。

**Q: 原型不完整怎么办？**
A: 不完整的信息标注为「待确认」，PRD 文档末尾汇总所有待确认项。

**Q: ZIP 包解压到哪里？**
A: 临时目录 `/tmp/html-to-prd-extract`，分析完成后自动清理。
