# zacc-prd-by-html — 产品需求文档反向工程

从产品原型文件（HTML/CSS/JS）反向推导并生成完整的 PRD 产品需求文档。通过结构化提取，将可视化产品形态转化为可执行的产品文档。

## Plan Mode 执行策略

本技能 **必须以 Plan Mode 执行**，确保 PRD 文档经过用户审批后才落盘。

1. **自动进入 Plan Mode**：技能触发后，第一步调用 `EnterPlanMode`
2. **Plan Mode 内完成全部分析**：输入检测、信息提取、PRD 生成全部在 Plan Mode 内完成，期间可读取文件和搜索代码，但 **禁止写入任何项目文件**
3. **Plan 完成后自动退出**：调用 `ExitPlanMode` 提交 PRD 内容等待用户审批
4. **用户审批通过后写入文件**：步骤 5 将 PRD 写入指定路径
5. **写入完成后停止**：输出确认信息后结束

## 输出文件

| 文件 | 默认位置 | 作用 |
|------|----------|------|
| PRD 文档 | `docs/prd/{产品名}.md` | 产品需求文档 |

> 用户可指定输出路径。默认路径基于产品名称生成。

## 执行步骤

### 步骤 0：输入类型门禁

**必须先于步骤 1 执行**，判断输入类型并选择处理策略。

**判定流程**（详见 [references/input-detection.md](references/input-detection.md)）：

1. 检查 `$ARGUMENTS` 是否以 `http` 开头 → 远程 URL
2. 检查路径是否指向 `.zip` 文件 → ZIP 压缩包
3. 检查路径是否指向 `.html` 文件 → 单文件 HTML
4. 检查路径是否为目录且包含 `.html` 文件 → HTML 目录
5. 以上均不满足 → 用 `AskUserQuestion` 提示用户重新指定

**非 HTML 输入的处理**：

| 输入类型 | 处理方式 |
|----------|----------|
| PDF / 图片 / Figma 链接 | 提示当前仅支持 HTML 原型，建议导出为 HTML 后重试 |
| 无参数 | 用 `AskUserQuestion` 询问原型文件路径 |

### 步骤 1：输入预处理

根据步骤 0 判定的输入类型执行预处理：

**单文件 HTML**：
- 用 Read 读取完整内容
- 提取内联 CSS（`<style>` 标签）和 JS（`<script>` 标签）
- 提取外链资源路径，逐个读取

**HTML 目录**：
- 用 Glob 扫描目录下所有 `.html` 文件
- 识别入口文件（`index.html` 或含 `home`/`main`/`landing` 的文件）
- 文件数量阈值：≤5 全量分析；6-15 重点分析入口+关键页；>15 入口+用户指定页

**ZIP 压缩包**：
- `unzip -l` 列出清单 → `unzip -d /tmp/html-to-prd-extract` 解压 → 按目录策略处理

**远程 URL**：
- 用 WebFetch 抓取页面内容
- 抓取失败时提示用户手动下载后重新执行

**通用预处理**（所有类型）：
- 编码检测：非 UTF-8 尝试转码，失败则提示
- 资源完整性：外链 CSS/JS 不可访问的标注"资源缺失"
- 页面可解析性：片段式 HTML 标注"非完整页面"

### 步骤 2：页面关系建模

**单文件**：跳过此步骤，直接进入步骤 3。

**多文件**：

1. **构建页面导航图谱**：从每个 HTML 文件的 `<a href>` 提取页面间链接关系
2. **识别入口页面**：被链接最多的页面 / `index.html` / 含 `home`/`main` 的文件
3. **识别页面层级**：导航栏中出现的页面为一级页面，通过操作跳转的为二级页面
4. **输出页面关系图**：

```markdown
📋 页面关系图谱：
- 入口页面：{name}
- 一级页面：{A}, {B}, {C}
- 二级页面：{A}→{D}, {B}→{E}
- 页面总数：{N}
```

### 步骤 3：六维度信息提取

根据步骤 2 的结果选择分析策略（详见 [references/parallel-analysis.md](references/parallel-analysis.md)）：

| 场景 | 策略 |
|------|------|
| 单文件 或 ≤5 页面 | 串行分析，无需 Agent |
| >5 页面 | 并行分析，按页面分配 Agent |

**六个提取维度**（提取方法详见 [references/html-extraction-guide.md](references/html-extraction-guide.md)）：

#### 3.1 产品概述提取

- **提取来源**：`<title>`、`<h1>`、logo、meta description、hero 区域
- **输出**：产品名称、Slogan、定位、目标用户、核心价值

#### 3.2 用户流程提取

- **提取来源**：`<a href>`、`<router-link>`、`<button>`、`<form action>`、JS 跳转
- **输出**：用户旅程图、页面间导航关系、关键交互节点、决策路径

#### 3.3 信息架构提取

- **提取来源**：DOM 层级（`<section>`/`<nav>`/`<main>`）、CSS class 命名、标题层级（h1-h3）
- **输出**：模块层级结构、导航体系、内容组织方式

#### 3.4 功能需求提取

- **提取来源**：`<form>`、`<button>`、`<input>`、`<table>`、列表渲染
- **输出**：功能模块拆解、用户故事、功能规则、输入/输出定义、异常处理

#### 3.5 交互设计规范提取

- **提取来源**：CSS 变量、color/font/border-radius/box-shadow 属性、JS 动画代码
- **输出**：色彩系统、字体规范、组件规范、动画与过渡

#### 3.6 数据需求提取

- **提取来源**：fetch/axios 调用、localStorage 操作、表单字段、列表渲染数据
- **输出**：数据实体、数据流转关系

**每个维度的提取结果格式**：

```markdown
### [维度名称]

**提取来源**：[文件路径:行号范围]

| 原型元素 | 提取信息 | 置信度 |
|----------|----------|--------|
| ... | ... | 高/中/低 |

**待确认项**：[置信度为中/低的项目]
```

**置信度判断标准**：
- **高**：原型中有明确对应的元素和内容
- **中**：从原型推断得出，逻辑合理但无直接证据
- **低**：原型中无对应信息，基于经验假设

### 步骤 4：PRD 文档生成

将步骤 3 的提取结果按 PRD 模板组装为完整文档。模板详见 [references/prd-template.md](references/prd-template.md)。

**章节生成规则**——只生成有对应提取结果的章节：

| 章节 | 生成条件 |
|------|---------|
| 1. 产品概述 | 始终生成 |
| 2. 用户流程 | 检测到页面导航或多页面 |
| 3. 信息架构 | 检测到模块结构 |
| 4. 功能需求 | 检测到交互元素 |
| 5. 各页面详细需求 | 多页面原型 |
| 6. 交互设计规范 | 检测到 CSS 样式信息 |
| 7. 非功能性需求 | 检测到性能/兼容性/无障碍相关代码 |
| 8. 数据需求 | 检测到表单/API/数据绑定 |
| 9. 运营策略 | 检测到 Banner/弹窗/推荐位 |
| 10. 待确认项汇总 | 始终生成（有待确认项时） |
| 11. 附录 | 始终生成 |

**关键规则**：
- 对原型中未体现的内容，标注 **"待确认"**，不臆测
- 每个功能需求标注原型对应位置（文件路径 + 元素定位）
- 置信度为中/低的结论在待确认项中汇总
- 交互规范只记录原型中实际使用的值，不推断设计系统

### 步骤 5：写入 PRD 文件

用户审批 Plan 后执行。

**输出路径确定**：

1. 用户指定了路径 → 使用用户指定路径
2. 用户未指定 → 默认 `docs/prd/{产品名}.md`（产品名从步骤 3.1 提取）

**文件已存在时**：

用 `AskUserQuestion` 询问：
- **覆盖**：备份旧文件为 `{产品名}_backup_{timestamp}.md`，然后写入
- **追加日期后缀**：写入 `{产品名}_{YYYYMMDD}.md`
- **取消**：中止操作

**执行清单**：

- [ ] 确保目录存在：`mkdir -p {目标目录}`
- [ ] 如有旧文件备份
- [ ] 用 Write 工具写入 PRD 文档
- [ ] 如使用临时目录（ZIP 解压），清理临时文件
- [ ] 输出确认信息

**输出确认**：

```
✅ PRD 文档生成完成！

📄 已写入: {路径}
📊 文档统计:
- 章节数：{N}（{生成条件满足的章节}）
- 功能需求数：{N}
- 待确认项：{N} 条
- 原型页面数：{N}

⚠️ 待确认项较多时，建议产品经理优先确认以下高优先级项：
{列出影响核心功能的待确认项}

💡 后续可使用 /task-init 基于此 PRD 生成技术方案和任务拆解
```

## 边界情况处理

详见 [references/edge-cases.md](references/edge-cases.md)。

核心原则：
- **不臆测**：原型中不存在的信息一律标注"待确认"
- **可追溯**：每个提取结论标注原型来源
- **结构完整**：即使内容为空也保留章节框架

---

## 注意事项

1. 生成 PRD 需要产品经理进一步审核和完善，它不是最终版
2. 保持客观，基于原型事实分析，如发现原型中的设计问题在附录中提出建议
3. 优先保证准确性，宁可多标注"待确认"也不臆测
4. 多页面原型的并行分析不超过 4 个 Agent，防止上下文碎片化
