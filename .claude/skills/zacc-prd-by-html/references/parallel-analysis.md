# 并行分析策略

> 供 zacc-prd-by-html 步骤 3 使用，定义多页面/复杂原型的并行分析策略。

## 触发条件

| 情况 | 策略 |
|------|------|
| 单 HTML 文件，页面结构简单（≤3 个主要模块） | **串行分析**，不启动 Agent |
| 单 HTML 文件，页面结构复杂（>3 个主要模块） | **串行分析**，按维度逐个提取 |
| 多 HTML 文件（2-5 个） | **串行分析**，逐页提取后整合 |
| 多 HTML 文件（>5 个） | **并行分析**，启动 Agent 分担页面分析 |
| 目录含子目录/多模块 | **并行分析**，按子目录分配 Agent |

## 串行分析流程（默认）

所有提取按以下顺序逐个执行，不需要 Agent：

1. 产品概述提取 → 2. 用户流程提取 → 3. 信息架构提取 → 4. 功能需求提取 → 5. 交互规范提取 → 6. 数据需求提取

每个维度的提取方法见 [html-extraction-guide.md](html-extraction-guide.md)。

## 并行分析流程（多页面时启用）

### Agent 分配策略

**不要按维度分配 Agent**（单文件内维度间有依赖），**按页面分配 Agent**：

```
主控（当前会话）：
  - 读取所有文件，建立页面关系图谱
  - 执行产品概述提取（需要全局视角）
  - 分配页面给各 Agent
  - 整合 Agent 结果，生成 PRD

Agent 1：分析 {页面A}
  - 提取该页面的用户流程、信息架构、功能需求、交互规范、数据需求
  - 输出格式按 html-extraction-guide.md 的提取结果格式

Agent 2：分析 {页面B}
  - 同上
```

### Agent Prompt 模板

```
你是 PRD 反向工程分析员。请分析以下 HTML 原型文件，提取产品需求信息。

**文件路径**：{path}
**页面名称**：{name}
**页面在整体流程中的位置**：{从主控的页面关系图谱中获取}

请按以下维度提取信息（提取方法参考项目中的 html-extraction-guide.md）：

1. 用户流程：该页面的入口、出口、关键交互节点
2. 信息架构：页面模块层级结构
3. 功能需求：每个操作按钮/表单对应的功能点，用用户故事描述
4. 交互设计：色彩、字体、组件、动画
5. 数据需求：表单字段、列表数据、API 调用

**输出格式**：每个维度用 markdown 表格，包含「原型元素」「提取信息」「置信度」三列。
置信度为中/低的项目，列入「待确认项」。

对原型中未体现的内容，标注「待确认」，不要臆测。
```

### 结果整合

1. 收集所有 Agent 的提取结果
2. 合并相同维度（如多个页面的功能需求合并为完整列表）
3. 消除冲突：不同页面的交互规范不一致时，以入口页面为准，在待确认项中标注
4. 补充跨页面的用户流程（主控完成）
5. 统一生成待确认项汇总

## 工具使用建议

- 单文件/少量页面：不需要 TeamCreate，直接用 Agent 工具启动子 Agent
- 大量页面（>10）：考虑 TeamCreate + TaskCreate 分配任务
- 避免启动超过 4 个并行 Agent，防止上下文碎片化
