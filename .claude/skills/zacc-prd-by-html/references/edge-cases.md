# 边界情况处理

> 供 zacc-prd-by-html 全流程使用，定义异常和边界情况的处理方式。

## 输入阶段

| 情况 | 处理方式 |
|------|----------|
| 文件不存在 | 提示用户确认路径，列出当前目录下可用的 `.html` 文件 |
| 文件为空（0字节） | 报错退出，提示文件无内容 |
| 非 HTML 文件（.pdf/.png/.fig 等） | 提示当前仅支持 HTML 原型，建议导出为 HTML 后重试 |
| HTML 不完整（片段、缺少 `<html>`/`<body>`） | 继续分析，在 PRD 待确认项中标注"原型为非完整页面" |
| 编码异常（乱码） | 尝试 UTF-8 / GBK / GB2312 转码；失败则提示用户转换编码后重试 |
| 远程 URL 抓取失败 | 提示用户手动下载后以本地文件方式重新执行 |
| ZIP 解压失败 | 检查文件是否损坏，提示用户重新打包 |

## 分析阶段

| 情况 | 处理方式 |
|------|----------|
| 原型内容太少（<5 个交互元素） | 生成精简版 PRD（仅含产品概述 + 功能清单 + 待确认项），提示原型信息不足以推导完整 PRD |
| 无法识别产品名称 | 使用文件名作为占位，标注"待确认" |
| 无明确导航关系（单页面无链接） | 仅分析当前页面，PRD 中标注"单页面原型，用户流程待补充" |
| CSS/JS 外链资源缺失 | 仅分析 HTML 结构和内联样式，缺失部分标注"资源缺失，交互规范待确认" |
| 多页面导航关系矛盾（循环/死链） | 记录实际链接关系，在待确认项中标注矛盾点 |
| 原型为纯静态展示（无交互元素） | 生成信息架构 + 内容需求为主，交互部分标注"无交互元素" |
| 原型含框架特定代码（React/Vue 模板语法） | 识别框架类型，提取逻辑层的路由/状态/事件绑定 |

## 输出阶段

| 情况 | 处理方式 |
|------|----------|
| 目标文件已存在 | 询问用户：覆盖 / 追加日期后缀（如 `PRD_产品名_20260423.md`）/ 取消 |
| 目录不存在 | 自动 `mkdir -p` 创建目标目录 |
| PRD 内容超过 3000 行 | 检查是否有过度展开的章节，提示可拆分为多个文档 |
| 待确认项超过 20 条 | 在待确认项汇总前增加优先级排序，标注哪些阻塞开发 |

## 质量兜底

无论任何情况，生成的 PRD 必须满足：

1. **不臆测**：原型中不存在的信息一律标注"待确认"
2. **可追溯**：每个提取结论标注原型来源（文件路径 + 元素定位）
3. **结构完整**：即使内容为空也保留章节框架，避免遗漏
