1. meta_completeness（Meta 机读表格完整性）：
   - 是否存在 `## 元数据 (Meta)` 章节
   - 表格是否含 8 个字段：feature-name / 需求类型 / 估计粒度 / 主模块路径 / 关联 Wiki 节点 / 涉及新接口 / 涉及路由变更 / 涉及全局状态变更
   - feature-name 是否用反引号 kebab-case（如 `bottom-sheet-voice-revamp`），值是否与文件名一致
   - 未知字段是否显式填 `unknown` 或 `TBD` 而非留空或保留 `{...}` 占位符

2. upstream_artifacts_table（上游产物摘要完整性）：
   - 是否存在 `## 上游产物摘要` 章节
   - 表格是否覆盖 4 行：CLAUDE.md / .claude/AI_RULES.md / wiki/index.json / wiki/glossary.md
   - 每行状态是否明确为「已加载」或「未找到」
   - 备注列是否包含有意义信息（技术栈摘要 / 红线条数 / 命中节点 ID 等），而非空白或占位

3. six_section_completeness（子需求六段式完整性）：
   - 是否存在至少一个 `## 一、{子需求标题}` 二级章节
   - 该章节下是否 6 段齐全：背景 / 现状问题 / 改造方案 / 验收标准 / 受影响文件 / 参考代码
   - 每段是否有实际内容，不能只有标题空段
   - 「背景」是否保留了用户原始描述（语音交互默认开始听 / 突兀 / 话筒按钮 / 关闭时停止等关键词至少命中 1 个）

4. acceptance_observable（验收标准可观察性）：
   - 「验收标准」条目是否全部为可测试的行为描述（如"点击话筒按钮后开始录音"、"BottomSheet 关闭时 isListening=false"）
   - 是否出现"体验更好"、"更流畅"、"合理"、"友好"等主观模糊描述（应扣分）
   - 条目是否可通过人工或自动化二值判定

5. global_constraints_inheritance（全局约束继承）：
   - 是否存在 `## 全局约束` 章节
   - 是否有「来自 AI_RULES.md 的红线」子段，并至少继承 1 条实际红线条目（而非仅"遵循 AI_RULES.md"一句话）
   - 是否有「本需求特有约束」子段，且引用了 wiki/nodes/component.bottom-sheet.md 的 Legacy Constraints

   - 「受影响文件」是否包含 wiki 节点 key_files 的候选项
   - 是否引用了 Legacy Constraints 中的具体条款（不是泛泛提到"有历史包袱"）

7. no_spillover_artifacts（无溢出产物）：
